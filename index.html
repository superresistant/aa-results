aa

An agent harness that runs a fleet of always-on agents in one daemon.

aa runs 200+ agents in parallel every day for two companies. These are its measurements with the AgentRAMBench runner, next to the published figures for other harnesses.

How to read it

  1. aa is one daemon holding all agents, with one terminal client attached in the measured tmux. The other harnesses run one full process per agent, each in its own pane. With one client per agent, add about 1.4 MiB per agent.
  2. Sessions idle for 300 s sleep inside the daemon (aa's default). The 1 h figure measures sleeping sessions; the other harnesses have no equivalent mode.
  3. The task, crash and fault tests drive aa headless through its local socket, as the others run headless (claude -p, codex exec, opencode run).
  4. All tests use a local mock model, tmux and default settings. No real model or API is called.
  5. aa is closed source. The adapter and binary are not public, so these aa figures cannot be reproduced by third parties; the method, runner and comparison figures can be checked.
  6. Same mock, scenarios and machine as the edition, on a different day. One run per idle point, three per crash test, two per fault profile, five for the task.

Method

Measured with the AgentRAMBench runner (github.com/agentrambench/bench, measured with commit ef0dbb2, measurement code identical to the final edition's a8e5273), following the method of AgentRAMBench edition 2026-11 (final, frozen 17 Nov 2026). Comparison figures from that edition (RAM, CPU, kill -9). The aa runs were done on 16 Nov 2026 (aa 1910537) and, for the fault row, on 24 Nov 2026 (aa 5a9d477c, same runner commit) by the author of aa, not by AgentRAMBench, on a 16-core, 64 GB Linux desktop.
